# Digital Stamp Card

A modern digital loyalty stamp system built with **Go + Gin** for the backend and **Next.js** for the frontend.

The project helps small businesses such as coffee shops, salons, barbers, bakeries, and restaurants reward repeat customers without using physical stamp cards.

---

## Features

### Customer Portal

* Scan permanent shop QR code
* Register with name and phone number
* View digital stamp card
* Continue previous stamp progress
* View stamp history
* View available rewards
* Scan temporary staff QR to receive a stamp
* Redeem reward after reaching the required number of stamps
* Mobile-first web experience
* No mobile app required

### Staff Portal

* Staff login
* Dashboard overview
* View customers
* Search customers
* View customer stamp progress
* Generate temporary stamp QR
* Give customer a stamp
* Redeem customer rewards
* View stamp and reward history

# Backend Architecture

![Digital Stamp Architecture](https://res.cloudinary.com/dtz0urit6/image/upload/q_auto:best,f_jpg/cloudinary-tools-uploads/wjvodaiagbrifrkt82gw)

The Go API follows a simple layered architecture.

```text
HTTP Request
    ↓
Gin Router
    ↓
Handler
    ↓
Service
    ↓
Repository
    ↓
MySQL
```

### Handler

Handles HTTP requests and responses.

### Service

Contains business logic.

Examples:

* Validate stamp QR
* Add stamp
* Check reward eligibility
* Redeem reward

### Repository

Handles database operations.

# QR Code Design

The system uses two different QR codes.

## Permanent Shop QR

Placed physically at:

* Cashier counter
* Table
* Entrance
* Receipt
* QR stand

Example:

```text
https://example.com/shop/good-coffee
```

Purpose:

```text
Open Customer Portal
```

It does **not** add a stamp.

---

## Temporary Stamp QR

Generated by staff after a customer makes a purchase.

Example flow:

```text
Staff Generate QR
    ↓
QR Valid For 60 Seconds
    ↓
Customer Scans
    ↓
+1 Stamp
    ↓
QR Becomes USED
```

A temporary QR can only be used once.

---

# Customer Session

The customer portal uses a session so returning customers do not need to enter their phone number every visit.

```text
Customer Scans Shop QR
        ↓
Session Valid?
   ↓             ↓
 YES             NO
   ↓              ↓
Open Card      Enter Phone
                  ↓
             Create Session
```

Customer sessions can stay valid for around:

```text
30 days
```

Session expiration does not remove customer stamps.

# Backend Setup

Go to backend:

```bash
cd gin-api
```

Install dependencies:

```bash
go mod tidy
```

Copy `.env.example` to `.env`, then configure it:

```env
PORT=8080

DATABASE_URL=mysql://app:app@localhost:3306/digital_stamp?ssl-mode=DISABLED

# Optional in production for verified Aiven TLS:
# DATABASE_CA_CERT_FILE=/etc/secrets/aiven-ca.pem

FRONTEND_URL=http://localhost:3000
```

Start MySQL locally. The API applies embedded migrations automatically when it starts:

```bash
docker compose up -d db
```

Run backend:

```bash
go run ./cmd/api
```

For local XAMPP MariaDB on Windows, create the local database/user once with
`gin-api/scripts/setup-xampp.sql`, then run:

```powershell
.\run-local.ps1
```

To create the first local staff account, run the interactive seed launcher
instead. It asks for the password securely and starts the API:

```powershell
.\seed-staff-local.ps1
```

API:

```text
http://localhost:8080
```

Health check:

```text
http://localhost:8080/api/health
```

# Frontend Setup

Go to frontend:

```bash
cd digital-stamp
```

Install dependencies:

```bash
bun install
```

Copy `.env.example` to `.env.local` and set:

```env
NEXT_PUBLIC_API_URL=http://localhost:8080/api
```

Run frontend:

```bash
bun dev
```

Open:

```text
http://localhost:3000
```

# Project Goal

The goal of this project is to solve a simple business problem:

> Small businesses need an easy way to encourage customers to return without relying on physical loyalty cards.

The Digital Stamp Card provides a simple mobile web experience where customers can collect stamps and redeem rewards, while staff can manage the loyalty process from a web dashboard.
